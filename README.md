# 锦鉴 · 面料样品管理与以图检索

锦鉴（Fabric Sample）是面向纺织面料场景的 Web 应用，由 **绍兴风禾信息科技有限公司** 开发，帮助企业集中管理样品图片、编号和业务参数，并通过上传图片查找相似面料。

项目将样品档案、自定义字段和图片检索串联起来，可用于技术学习、业务验证与二次开发。真实检索接入百度智能云面料图片搜索，另提供无需云服务密钥的本地演示模式。当前版本为免登录 Demo，尚未包含用户权限、多租户等完整生产能力。

公司官网：[风禾科技 · 企业数字化与企业 AI 落地](https://www.efhkj.com)。我们提供本项目的**私有化部署、功能定制与系统集成服务**，详见[关于风禾科技](#关于风禾科技与商业服务)。

本项目采用 [GNU GPLv3](LICENSE) 开源协议，允许个人与企业使用、修改，以及遵守许可的商业使用。

## 功能

- 样品创建、编辑、搜索和删除；编号唯一、创建后不可修改。
- 每个样品 1–12 张图片，支持追加、预览、删除与入库失败重试。
- 全局自定义字段：文本、数字、下拉选项；必填、排序及结果展示配置。
- 百度智能云面料图库入库与搜索，根据业务标识批量补齐样品信息。
- 同一样品多张图片取最高分，只展示一次；展示实际命中图片。
- 业务软删除立即过滤搜索结果；百度端删除失败有独立重试列表。
- 支持彩色样品展示与灰度纹理检索；提供适配移动端的操作页面。
- 正式业务使用百度检索，本地匹配只供开发测试。

## 环境变量

仓库提供两份不含真实密钥的示例，按启动方式选择：

- [`server/.env.example`](server/.env.example)：本地开发或直接运行 Node.js 时复制为 `server/.env`。
- [`.env.example`](.env.example)：Docker Compose 部署时复制为根目录 `.env`。

根目录 `.env` 用于 Compose 变量替换，不会自动成为本地 Node.js 后端配置；后端从 `server/.env` 读取配置。真实配置文件均被 Git 忽略，请勿提交数据库密码、百度密钥或客户数据。前端通过同源路径访问 API，无需额外的前端环境变量文件。

| 变量                                              | 用途与设置                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| `DATABASE_URL`                                    | 本地后端的 PostgreSQL 连接串；Compose 自动生成                          |
| `POSTGRES_PASSWORD`                               | Compose 数据库密码，必须配置；推荐长随机字母数字字符串                  |
| `HOST` / `PORT`                                   | 后端监听地址与端口，本地默认 `127.0.0.1:3001`；容器内为 `0.0.0.0:3001`  |
| `STORAGE_DIR`                                     | 图片目录，相对路径以后端工作目录 `server/` 为基准；Compose 使用持久化卷 |
| `SEARCH_MODE`                                     | 示例为 `demo`；接入真实检索时改为 `baidu`，不自动回退至 demo            |
| `BAIDU_AUTH_MODE`                                 | `oauth`（应用密钥）或 `aksk`（安全认证 AccessKey）                      |
| `BAIDU_API_KEY` / `BAIDU_SECRET_KEY`              | OAuth 模式所需凭据                                                      |
| `BAIDU_ACCESS_KEY_ID` / `BAIDU_ACCESS_KEY_SECRET` | AK/SK 模式所需凭据                                                      |
| `BAIDU_SEARCH_TYPE`                               | 默认 `materiel`，须开通对应图库                                         |
| `CORS_ORIGIN`                                     | 本地后端允许的浏览器来源，多个来源用逗号分隔；不是访问权限控制          |

`TEST_API_URL`、`REINDEX_API_URL` 和 `SCREENSHOT_DIR` 是验证与迁移脚本的可选参数，须在执行命令时传入，脚本不自动读取上述 `.env` 文件。密钥修改后重启应用生效。

## 本地启动（无需 Docker）

需要 Node.js 24 和 npm。将仓库克隆或下载到本地后，进入项目根目录执行：

```sh
npm ci
cp server/.env.example server/.env
npm run db:generate
```

终端 1 启动本地 PostgreSQL（首次自动初始化；再次启动保留数据）：

```sh
npm run db:local
```

终端 2 创建数据库表并启动应用：

```sh
npm run db:push
npm run dev
```

访问 [前端页面](http://127.0.0.1:5173)。后端地址为 `http://127.0.0.1:3001`，可通过 [`/api/health`](http://127.0.0.1:3001/api/health) 检查服务状态。数据库不可用时健康接口仍可能返回，需实际创建样品验证数据库连接。

数据库为 `fabric_sample`，开发用户名 `fabric`、密码 `fabric_local`，仅监听本机；数据在 `.local-postgres/`。已有 PostgreSQL 时可跳过 `db:local`，修改 `server/.env` 中 `DATABASE_URL`。本地数据库脚本是开发辅助，部署使用独立数据库。

### 开发测试

环境变量示例默认 `SEARCH_MODE=demo`，仅供开发测试使用；客户环境必须使用 `SEARCH_MODE=baidu`，不会自动回退到本地匹配。应用启动后可通过 `npm run seed:demo` 生成测试样品，禁止向客户数据库导入测试数据。

### 如何使用

1. 打开“字段设置”，按业务需要添加成分、克重、幅宽等字段，设置必填与搜索结果展示项。
2. 在“样品管理”中新建样品，填写唯一编号、名称及参数，上传 1–12 张图片。
3. 在“以图搜样品”上传查询图，调整结果数量和最低相关度，查看命中图片与样品信息。
4. 在样品详情中追加或删除图片；真实百度模式下，入库失败可点击“重新入库”，图库删除失败可在清理列表重试。

演示模式使用本地图片匹配，不代表百度面料检索的效果；切换模式后，已有图片需在对应模式重新入库。

## 百度真实接入

1. 在百度智能云控制台创建图像搜索应用，申请并开通**面料图片搜索图库**。
2. 应用密钥：设 `BAIDU_AUTH_MODE=oauth`，填写 `BAIDU_API_KEY` 和 `BAIDU_SECRET_KEY`。若使用安全认证 AccessKey，设 `BAIDU_AUTH_MODE=aksk`，填写 `BAIDU_ACCESS_KEY_ID` 和 `BAIDU_ACCESS_KEY_SECRET`；采用 BCE V1 签名，不再获取 OAuth token。
3. 设置 `SEARCH_MODE=baidu`、`BAIDU_SEARCH_TYPE=materiel`，重启服务。
4. 创建样品；之前因缺少密钥入库失败的图片，可在样品详情点击“重新入库”。

官方文档：[百度智能云图像搜索](https://ai.baidu.com/ai-doc/IMAGESEARCH/kl6xkl6kq)。百度图库的开通条件、额度与收费以官方为准，软件许可不包含第三方服务费用。

入库仅发送灰度检索图片及样品编号摘要 `{"code":"样品编号"}`。检索后先提取编号，按编号批量读取业务数据库，再利用百度返回的 `cont_sign` 定位本地命中图片。样品名称、自定义参数和图片地址都从我们自己的系统获取。名称、自定义参数修改只更新业务数据库。

查询最多拉取百度返回的前 300 张候选图片，再按样品去重和阈值筛选。列表数量可选 10/20/50；若符合条件的样品不足，返回实际数量。百分比分数为相关性，并非同款概率。

图片每次上传最多 10 MB，后台实际解码校验，限制 4000 万像素；处理成最长边不超过 1600 像素的 JPEG，生成缩略图并检查编码后的请求大小。样品彩色图片、彩色缩略图和灰度检索派生图永久保存；查询图在内存中处理，不入库、不落盘。

## 构建与部署

### 直接部署 Node.js 应用

服务器需要 Node.js 24、npm 和可连接的 PostgreSQL。首次部署先安装依赖，复制环境示例并填写实际连接串、百度凭据。以下命令从项目根目录执行：

```sh
npm ci
cp server/.env.example server/.env
# 编辑 server/.env；配置真实数据库及 SEARCH_MODE=baidu
npm run db:generate
npm run db:push
npm run build
npm start
```

生产运行时，NestJS 同时提供 `client/dist` 静态页面与 API，默认访问 [应用页面](http://127.0.0.1:3001)。图片默认写入 `server/data/uploads/`。建议使用进程管理器或系统服务保持应用运行，通过反向代理配置域名、HTTPS 与访问认证。

### Docker Compose 部署

需要 Docker Engine / Docker Desktop 与 Docker Compose v2。复制根目录环境变量示例，替换 `POSTGRES_PASSWORD` 为长随机密码；先体验可保持 `demo`，实际使用须改为 `baidu` 并填写相应凭据。

```sh
cp .env.example .env
# 编辑 .env 后启动
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

访问 [应用页面](http://127.0.0.1:3001)。Compose 使用 PostgreSQL 17 与 `postgres_data`、`uploads` 两个持久化卷，启动时自动同步数据库表。宿主机端口只绑定 `127.0.0.1`，数据库不向宿主机暴露端口。

更新代码后执行 `docker compose up --build -d`；修改根目录 `.env` 后执行 `docker compose up -d` 重新创建应用容器。停止服务使用 `docker compose down`，不要添加 `-v`，否则会删除数据库及图片卷。已有数据库卷不会因修改 `POSTGRES_PASSWORD` 自动更新数据库密码，需要同步修改数据库内的账号密码。

### 正式使用前

- 当前所有访问者都能管理样品、字段和图片。对外开放前应增加登录与权限控制，或在反向代理、VPN 层限制访问；CORS 不提供认证。
- 备份 PostgreSQL 和图片目录/卷，二者需共同恢复。软删除保留本地图片，不自动释放存储空间。
- `db push` 用于当前 Demo 的表结构同步，升级前备份数据；持续生产迭代建议引入版本化数据库迁移。
- 真实检索依赖百度云网络与图库服务；需要完全内网检索时，可联系我们定制替代方案。

## API

| 方法                 | 路径                         | 说明                                               |
| -------------------- | ---------------------------- | -------------------------------------------------- |
| GET                  | /api/health                  | 搜索模式和配置状态（不返回密钥）                   |
| GET / POST           | /api/samples                 | 分页查样品 / 创建（multipart：data JSON + images） |
| GET / PATCH / DELETE | /api/samples/:id             | 详情 / 更新 / 软删除                               |
| POST                 | /api/samples/:id/images      | 追加图片（multipart：images）                      |
| DELETE               | /api/images/:id              | 删除图片（保留至少一张）                           |
| POST                 | /api/images/:id/retry-index  | 重试入库                                           |
| GET / POST           | /api/custom-fields           | 查询 / 新建字段                                    |
| PATCH / DELETE       | /api/custom-fields/:id       | 编辑 / 移除字段                                    |
| POST                 | /api/image-search            | 搜索（multipart：image、limit、minScore）          |
| GET                  | /api/cleanup-tasks           | 百度删除失败列表                                   |
| POST                 | /api/images/:id/retry-delete | 重试图库清理                                       |

字段标识和类型创建后固定，移除字段不会删除历史参数值。已删除样品的编号与图片哈希保留，避免旧百度命中被错误关联至新样品。上传、检索错误以明确提示返回，百度服务失败不会伪装成“没有匹配结果”。

## 数据库配置与连接

本地部署的数据库凭据保存在不应提交的 `server/.env`。Prisma 使用 `DATABASE_URL`，格式为 `postgresql://用户名:密码@主机:端口/数据库?schema=public`，用户名及密码中的特殊字符需进行 URL 编码。当前应用不读取独立的 `PG_HOST`、`PG_PASSWORD` 等变量，修改连接信息时直接修改 `DATABASE_URL`。Compose 中该连接串由根目录的数据库密码自动生成。

数据库暂时不可达时，页面仍可打开，业务操作返回连接失败，不读取旧本地数据库，也不返回模拟搜索结果。确认数据库连接后运行 `npm run db:push` 创建表。

## 已知边界

- 原图及数据库文件使用本地持久化存储，备份时须同时备份两者；软删除不会自动清理本地文件。
- 入库请求若已被百度接受但响应丢失，重试可能收到重复图片错误。Demo 不自动猜测签名，请在百度控制台排查并修复对应记录。
- 搜索效果受拍摄距离、光照、背景与纹理细节影响，必须用真实面料样本评估；可另建相似图图库对比，不能跨图库直接复用索引。
- 没有后台重试队列，失败后通过页面手动重试；没有登录、权限、审计、批量导入或多租户。

## 灰度纹理检索

默认检索版本为 `texture-gray-v1`。样品上传后保留彩色图片用于展示，自动生成 `*-texture.jpg` 灰度 JPEG；百度只接收灰度图及样品编号。查询图使用相同灰度处理，结果通过百度签名关联回本地彩色图片。灰度分数表示图片相关性，不代表同款概率或实际成分、规格。

升级已有项目时，先停止旧服务，执行 `npm run db:push` 添加 `searchImagePath`、`indexProfile` 两个可空字段，再执行 `npm run build` 和 `npm start`。在另一个终端执行 `npm run reindex:texture`，按样品逐图删除旧彩色索引、生成灰度文件并重新入库；记录完成版本后重复运行会跳过已迁移图片。非本机服务可设置 `REINDEX_API_URL`。失败记录保留错误信息，可重跑或在样品详情重试。旧彩色索引及未完成迁移的图片不会参与灰度检索。

迁移期间对应图片可能短暂不可检索；删除旧百度索引失败时保留原签名以便重试。删除成功而灰度入库失败时，保留彩色原图、业务参数和灰度文件，修复后重新入库。灰度处理并不能完全消除亮度、光照、角度、尺度和背景造成的差异；花纹的色彩边界也可能丢失，需用真实客户照片验证。
